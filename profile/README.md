## 何をしている会社か

「作って終わり」ではなく、**事業の課題を聞くところから、作ったあとに回し続けるところまで**を一緒にやります。

- プロダクトの 0→1 開発（要件整理・設計・実装・リリース・運用）、POC / MVP 開発
- 既存プロダクトの開発チーム支援（技術顧問 / CTO支援 / 技術的負債の解消 / アーキテクチャ刷新）
- AIエージェント・社内ツール開発（Slack Bot、業務自動化、レポート自動生成）
- データ基盤・集計パイプライン（GA4 / Search Console / 広告API / クローラー）
- Web フロントエンド実装（Next.js / Astro、デザイナーの意図を汲んだ画面実装）

## 私たちの動き方

「○○をやってほしい」という依頼をそのまま受けるよりも、**中身を見させていただいた上で提案し、実行まで進める**のが得意です。機能を作るチームが開発に集中できるように、CI やインフラなどの足元の仕事を引き受けます。

### 課題を見つけるところから始める

依頼するタスクを用意していただく必要はありません。リポジトリやチームの状況を拝見し、開発を妨げている原因と、何をどう変えるとよいかを先にお出しします。作らない方がいい、と言うこともあります。

### 後回しになりがちな改善を計画して進める

障害対応のような急ぎの仕事は、社内で対応していただきます。私たちは、重要だけれど急ぎではないために後回しになっている改善を受け持ちます。

| | 緊急度が高い | 緊急度が低い |
|---|---|---|
| **重要度が高い** | 社内ですぐに対応する（障害からの復旧など） | **adding が計画して進める**（CI の高速化、ライブラリの計画的な更新、テストの整備など） |
| **重要度が低い** | 手間をかけずに済ませる | 必要かどうかを見直す |

### 一つの改善から始めて広げる

効果がいちばん大きいテーマを一つ選んで始め、回り始めたら次のテーマに移ります。

### 了承をもらってから進める

定例やチャットで相談を受け、進め方を短い提案にまとめて、了承をもらってから着手します。進み具合、次に出すもの、判断してほしいことは、定期的に報告します。

### 仕組みにして引き継ぐ

人に頼っていた作業を、コマンド、CI の検査、IaC、手順書に置き換えます。私たちが抜けたあとも、チームだけで回せるようにします。

### AI に任せても事故にならない形で使う

AI への頼み方をチーム共通の手順にまとめ、主ブランチへの直接 push のような危ない操作は仕組みで止めます。そのうえで、依存の更新やテストの追加といった定常の作業を AI に任せます。

## こんな相談に使ってください

### ライブラリアップデートの AI 化（セキュリティアップデートを含む）

Dependabot / Renovate の PR が溜まり続けている、脆弱性アラートが放置されている、といった状態を AI エージェントを組み込んだ運用で解消します。

- 依存ライブラリの更新 PR を AI が確認し、changelog・破壊的変更の調査から必要なコード修正、テスト実行までを下書き
- 本番に影響するものから順に更新し、緊急のセキュリティパッチをすぐ当てられる状態にする
- 人はレビューとマージ判断に集中できる状態にする

> 実績: ライブラリの緊急セキュリティパッチを、公表の翌日に本番へ。AI に任せた定常の変更を 350 件以上取り込み

### デプロイの高速化・安定したリリースフローの確立

「デプロイに時間がかかる」「リリースのたびに誰かが張り付いている」「本番で壊れるのが怖くて出せない」を解消します。

- CI/CD のビルド・テスト時間の短縮（キャッシュ、並列化、不要なジョブの整理）
- 誰でもリリースを出せる手順と、すぐに戻せるロールバック手段の整備
- 監視・アラート・エラー通知まで含めて、気軽に出せるリリースフローを作る

> 実績: デプロイ時間の中央値を 20.3分から 8.7分に短縮。1人に集中していたリリースを、画面のボタンから誰でも出せる形に

### 開発のルールを CI の検査で守る

「レビュー待ちで機能が出せない」「レビューする人によって指摘が違う」を解消します。

- プロジェクト固有の設計ルールを、CI で止まる独自の検査にする
- 環境の用意や定型の変更をコマンドと自動生成に寄せ、手作業の抜け漏れをなくす
- モックに頼りすぎず、本物のデータベースで確かめるテストに寄せる

> 実績: 設計ルールを 12 個の独自検査にし、人のレビューで見落としていた書き忘れを既存コードから 20 件発見

### クラウドインフラのコスト削減（AWS / Google Cloud など）

「請求額が年々増えているが、何にかかっているのか分からない」「とりあえず大きめの構成のまま動かしている」といった状態を見直します。

- 請求明細とリソースの利用状況を突き合わせて、削減できる余地を洗い出し
- インスタンスサイズの適正化、使われていないリソースの整理、割引プラン（Savings Plans / CUD など）の検討
- パフォーマンスを落とさない範囲で、アーキテクチャの見直しまで踏み込む

> 実績: 30日分の請求を項目ごとに調べ、使っていないデータの複製と定期バッチ 9 件を停止

「まずは現状を診断してほしい」「どこから手を付けるべきか分からない」という段階でも大丈夫です。お気軽に[お問い合わせ](#お問い合わせ)ください。

## チームで入る、ということ

フリーランス1人に頼むのとも、受託会社に丸投げするのとも違う形を目指しています。

| | adding の場合 |
|---|---|
| 体制 | 岩崎・植田の2人で入ります。元スタートアップ CTO と元リードエンジニアの組み合わせで、設計と実装、開発と運用を分担しながら進めます |
| 意思決定 | 間に営業やPMを挟まないので、仕様の相談からコード反映までが速い |
| 開発スタイル | Claude Code / Codex などの AI コーディングエージェントをチームで活用。ADR やデザインドキュメント、AGENTS.md を整備した状態で引き渡します |
| 経営の視点 | スタートアップ CTO 経験・自社事業の経営経験があるので、「技術的に正しい」だけでなく「事業として何を優先するか」から話せます |
| 採用の代わりに | 専任の採用を待たずに始められます。インフラ、CI/CD、監視をまとめて受け持ちます |
| 関わり方 | スポット、月額の伴走支援、技術顧問のいずれも可能。契約を終えるときは、一緒に作った仕組みと手順を社内に引き継ぎます |

### 支援事例

**CI・デプロイ・監視などの開発基盤の改善**
機能を作るチームの横に入り、CI・デプロイ・テスト・監視・インフラ・セキュリティをまとめて見直し。デプロイ時間の中央値を 20.3分から 8.7分に短縮し、1人に集中していたリリースを誰でも出せる形に。プロジェクト固有の設計ルールを 12 個の独自検査にしたところ、人のレビューで見落としていた書き忘れが既存コードから 20 件見つかった。

**技術の意思決定を、経営の言葉にする（CTO支援）**
エンジニア出身でない経営者と週次定例で技術戦略を策定。技術的負債を整理して優先順位を付け、外部リソースの活用も含めた解消計画に落とし込み。自社エンジニアの時間を守りながら負債を解消。

**BtoB 新規開拓の営業オペレーションを仕組み化（AIエージェント）**
リスト作成・企業調査・問い合わせフォーム対応を AI エージェントに分担。判断基準を言語化し、人は最終判断だけを行う運用に。

**広告レポート業務の AI 化**
月末月初の数値集計とコメント書きを AI が下書きし、人は確認と仕上げに集中。「作る仕事」から「確認する仕事」へ。

## 進め方

1. **壁打ち** — まず課題を聞きます
2. **現状の拝見と提案** — リポジトリやチーム、業務の状況を拝見し、「人が判断すべきこと」と「仕組みに任せられること」を切り分けたうえで、何から変えるかをご提案します
3. **一つ小さく始める** — いちばん効果の大きいテーマを一つ選んで着手します
4. **報告しながら広げる** — 進み具合と判断してほしいことを定期的に共有し、回り始めたら次のテーマに移ります
5. **引き継ぐ** — 仕組みと手順を整えた状態で社内に引き渡すか、伴走を続けます
