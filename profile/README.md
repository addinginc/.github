## 何をしている会社か

「作って終わり」ではなく、**事業の課題を聞くところから、作ったあとに回し続けるところまで**を一緒にやります。

- プロダクトの 0→1 開発（要件整理・設計・実装・リリース・運用）、POC / MVP 開発
- 既存プロダクトの開発チーム支援（技術顧問 / CTO支援 / 技術的負債の解消 / アーキテクチャ刷新）
- AIエージェント・社内ツール開発（Slack Bot、業務自動化、レポート自動生成）
- データ基盤・集計パイプライン（GA4 / Search Console / 広告API / クローラー）
- Web フロントエンド実装（Next.js / Astro、デザイナーの意図を汲んだ画面実装）

## こんな相談に使ってください

「○○をやってほしい」という依頼をそのまま受けるよりも、**中身を見させていただいた上で提案し、実行まで進める**のが得意です。

### ライブラリアップデートの AI 化（セキュリティアップデートを含む）

Dependabot / Renovate の PR が溜まり続けている、脆弱性アラートが放置されている、といった状態を AI エージェントを組み込んだ運用で解消します。

- 依存ライブラリの更新 PR を AI が確認し、changelog・破壊的変更の調査から必要なコード修正、テスト実行までを下書き
- CVE などのセキュリティアップデートは優先度を付けて先に処理
- 人はレビューとマージ判断に集中できる状態にする

### デプロイの高速化・安定したリリースフローの確立

「デプロイに時間がかかる」「リリースのたびに誰かが張り付いている」「本番で壊れるのが怖くて出せない」を解消します。

- CI/CD のビルド・テスト時間の短縮（キャッシュ、並列化、不要なジョブの整理）
- 手作業が残るリリース手順の自動化と、すぐに戻せるロールバック手段の整備
- ステージング環境・監視・エラー通知まで含めて、気軽に出せるリリースフローを作る

### クラウドインフラのコスト削減（AWS / Google Cloud など）

「請求額が年々増えているが、何にかかっているのか分からない」「とりあえず大きめの構成のまま動かしている」といった状態を見直します。

- 請求明細とリソースの利用状況を突き合わせて、削減できる余地を洗い出し
- インスタンスサイズの適正化、使われていないリソースの整理、割引プラン（Savings Plans / CUD など）の検討
- パフォーマンスを落とさない範囲で、アーキテクチャの見直しまで踏み込む

「まずは現状を診断してほしい」「どこから手を付けるべきか分からない」という段階でも大丈夫です。お気軽に[お問い合わせ](#お問い合わせ)ください。

## チームで入る、ということ

フリーランス1人に頼むのとも、受託会社に丸投げするのとも違う形を目指しています。

| | adding の場合 |
|---|---|
| 体制 | 岩崎・植田の2人で入ります。元スタートアップ CTO と元リードエンジニアの組み合わせで、設計と実装、開発と運用を分担しながら進めます |
| 意思決定 | 間に営業やPMを挟まないので、仕様の相談からコード反映までが速い |
| 開発スタイル | Claude Code / Codex などの AI コーディングエージェントをチームで活用。ADR やデザインドキュメント、AGENTS.md を整備した状態で引き渡します |
| 経営の視点 | スタートアップ CTO 経験・自社事業の経営経験があるので、「技術的に正しい」だけでなく「事業として何を優先するか」から話せます |
| 関わり方 | スポット開発、月額の伴走支援、技術顧問のいずれも可能。まずは小さく始めて、効果を見てから広げます |

### 支援事例

**技術の意思決定を、経営の言葉にする（CTO支援）**
エンジニア出身でない経営者と週次定例で技術戦略を策定。技術的負債を整理して優先順位を付け、外部リソースの活用も含めた解消計画に落とし込み。自社エンジニアの時間を守りながら負債を解消。

**BtoB 新規開拓の営業オペレーションを仕組み化（AIエージェント）**
リスト作成・企業調査・問い合わせフォーム対応を AI エージェントに分担。判断基準を言語化し、人は最終判断だけを行う運用に。

**広告レポート業務の AI 化**
月末月初の数値集計とコメント書きを AI が下書きし、人は確認と仕上げに集中。「作る仕事」から「確認する仕事」へ。

## 進め方

1. **壁打ち** — まず課題を聞きます。作らない方がいい、と言うこともあります
2. **業務の棚卸し** — 「人が判断すべきこと」と「仕組みに任せられること」を切り分けます
3. **小さく作って試す** — 最初から大きなシステムは作りません。1つの業務で試して効果を確認
4. **定着させて広げる** — 運用に乗せ、ドキュメントとコードを整備した状態で引き渡し or 伴走を続けます
